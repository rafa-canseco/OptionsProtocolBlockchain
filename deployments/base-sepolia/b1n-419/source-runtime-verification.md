# B1N-419 exact source/runtime verification

`script/fund/verify-meta-wheel-source-runtime.mjs` produces the locally compiled evidence used by the Base Sepolia
Meta Wheel handoff. It does not submit source code to Blockscout or Sourcify and never broadcasts a transaction. Its
only network operations are Base Sepolia JSON-RPC reads.

The verifier fails closed unless all of the following are true:

- the exact core Foundry build-info retains all 316 deployment-build sources and literal source contents;
- the earlier library Foundry build-info retains its exact 170-source closure and has an empty link map;
- solc is `0.8.24+commit.e11b9ed9`;
- only `settings.outputSelection` is reduced: 20 core FQNs are compiled from the 316-source build and five library
  FQNs from the 170-source build; all optimizer settings, metadata settings, `viaIR`, EVM version and remappings
  remain exact;
- the core build retains the exact five-address link map while the library build remains unlinked;
- recompiling each FQN from its deployment build-info reproduces its original creation bytecode, runtime template
  and metadata;
- the inventory contains exactly 47 distinct deployment addresses, 20 primary artifacts and five library artifacts,
  with the exact `34 + 7 + 1 + 5` origin split recorded by the live deployment;
- every inventory `creationCode`, `constructorArgs` and `initCode` composition and Keccak-256 hash is internally
  consistent and the creation code equals the artefact selected from the correct deployment build;
- all 39 top-level deployment transaction inputs equal recompiled creation bytecode plus constructor arguments;
- the eight internal deployments retain their trace-derived constructor arguments and recompile from the same
  source artifacts; and
- `eth_getCode` at the approved confirmation block equals the recompiled runtime byte-for-byte at all 47 addresses.

The runtime comparison resolves compiler-declared immutable ranges rather than ignoring them. It validates direct
constructor immutables, OpenZeppelin implementation self-addresses, Solidity library deployment addresses, the Fund
factory/deployer binding and the fixed six-decimal USDC binding before comparing the complete runtime.

Do not minimize either Standard JSON source closure. With `viaIR`, removing otherwise unrelated sources changes source
and AST identifiers and can change generated bytecode while leaving metadata unchanged. All 316 core sources and all
170 library-deployment sources must remain in their respective compiler inputs; target-only `outputSelection` is the
safe memory reduction.

## Generate evidence

```bash
node script/fund/verify-meta-wheel-source-runtime.mjs \
  --core-build-info "$B1N419_CORE_BUILD_INFO_PATH" \
  --library-build-info "$B1N419_LIBRARY_BUILD_INFO_PATH" \
  --inventory "$B1N419_VERIFICATION_INVENTORY_PATH" \
  --rpc-url "$BASE_SEPOLIA_RPC_URL" \
  --confirmation-block "$B1N419_SOURCE_RUNTIME_CONFIRMATION_BLOCK" \
  --source-commit "$B1N419_SOURCE_COMMIT" \
  --deployment-id "$B1N419_DEPLOYMENT_ID" \
  --unconfirmed-manifest-sha256 "$B1N419_UNCONFIRMED_MANIFEST_SHA256" \
  --solc "$B1N419_SOLC_PATH" \
  --output "$B1N419_SOURCE_RUNTIME_EVIDENCE_OUTPUT"
```

The output path must not already exist. The JSON contains no timestamps or local paths, so the same two build-info
files, inventory, chain state and approved identifiers reproduce the same semantic evidence.

## Reproduce an existing sidecar

```bash
node script/fund/verify-meta-wheel-source-runtime.mjs \
  --core-build-info "$B1N419_CORE_BUILD_INFO_PATH" \
  --library-build-info "$B1N419_LIBRARY_BUILD_INFO_PATH" \
  --inventory "$B1N419_VERIFICATION_INVENTORY_PATH" \
  --rpc-url "$BASE_SEPOLIA_RPC_URL" \
  --confirmation-block "$B1N419_SOURCE_RUNTIME_CONFIRMATION_BLOCK" \
  --source-commit "$B1N419_SOURCE_COMMIT" \
  --deployment-id "$B1N419_DEPLOYMENT_ID" \
  --unconfirmed-manifest-sha256 "$B1N419_UNCONFIRMED_MANIFEST_SHA256" \
  --solc "$B1N419_SOLC_PATH" \
  --check "$B1N419_SOURCE_RUNTIME_EVIDENCE_PATH"
```

Every option also has the environment-variable form shown above. `B1N419_SOLC_PATH` is optional only when the exact
compiler is available as `solc` on `PATH`.

## Finalizer integration contract

The finalizer should run `--check`, then SHA-256 the exact evidence file and require:

- `method == "SOLC_STANDARD_JSON_RPC_EXACT_V2"`;
- `exactSourceRuntimeBytecodeVerified == true`;
- matching `sourceCommit`, `deploymentId`, `unconfirmedManifestSha256`, Base Sepolia chain ID and confirmation block;
- non-zero top-level `coreBuildInfoSha256`, `libraryBuildInfoSha256`, `coreStandardJsonInputSha256`,
  `libraryStandardJsonInputSha256`, `inventorySha256`, and exact top-level `addressCount == 47` /
  `artifactCount == 25` bindings;
- `compiler.coreSourceCount == 316`, `compiler.librarySourceCount == 170`,
  `compiler.coreTargetArtifactCount == 20`, `compiler.libraryTargetArtifactCount == 5`,
  `compiler.targetArtifactCount == 25`, `compiler.fullSourceSetsRetained == true` and
  `compiler.targetOnlyOutputSelection == true`;
- `inventory.addressCount == 47`, `inventory.artifactCount == 25`, `inventory.primaryArtifactCount == 20` and
  `inventory.libraryArtifactCount == 5`;
- summary counts `creationVerified == 47`, `compiledRuntimeVerified == 47`, `rpcRuntimeVerified == 47`, plus exact
  compiled-artifact/top-level/internal counts `25`, `47`, `39` and `8`; and
- exactly 47 unique records with all three bytecode-match flags true.

The finalizer must also compare the records one-to-one against
`canonicalization-evidence.contractReceipts[] + library-prephase.orderedLibraries[]` by normalized address,
transaction hash and runtime code hash. Matching only the count or the sidecar digest would not bind the source proof
to the receipt inventory being handed to backend and allocator consumers.

The evidence-file SHA-256, both build-info SHA-256 digests and the inventory SHA-256 should be copied into the
canonical manifest's verification-evidence binding. `readiness.exactSourceRuntimeBytecodeVerified` may become true
only after this command passes. Public explorer verification is separate observability and must not rewrite the
canonical manifest.

## Deterministic fixture

Run the no-network fixture with:

```bash
node script/fund/test-meta-wheel-source-runtime-verifier.mjs
```

It covers the 316-core/170-library source closures, 20+5 artefact split, 47-address topology, exact origin split,
direct and self-address immutables, deterministic reproduction, and fail-closed behavior for altered runtime,
missing sources in either build, duplicate addresses, changed core or library compiler output, an incorrect core
link map and a non-empty library link map.
